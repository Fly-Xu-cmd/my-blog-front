# 博客后续迭代路线

用户于 2026-11-19 授权按路线实施。每轮独立评审、PR 与验收，目标 main；不自动合并或操作正式数据库、删除正式文件。前后台分别交付，新增 API 能力先发布前台后发布后台。

| 轮次 | 范围 | 验收重点 | 状态 |
| --- | --- | --- | --- |
| 1 | 七牛响应式图片、本地上传退役与只读旧链接审计 | 缩略图、异常回原图、安全 URL、无本地写入、部署不依赖旧目录 | 代码与隔离验收通过，独立评审中；正式旧引用待发布前核查 |
| 2 | 写作本地草稿、刷新恢复、离开提醒、文章历史版本与手动恢复 | 失败不丢稿、版本冲突、URL 与发布状态保持 | 待实施 |
| 3 | 基础站点名称、头像、首页介绍、联系方式和二维码配置 | 预览、公开/管理配置一致、失败与并发保护 | 待实施 |
| 4 | 首页主推文章、推荐系列与阅读入口 | 仅公开内容、隐藏后兜底、不依赖最新一篇 | 待实施 |
| 5 | 文章与笔记统一搜索、类型筛选、命中片段、高亮 | 可见性、总数与分页、乱序响应 | 待实施 |
| 6 | 阅读位置、最近阅读、稍后再读 | 本地数据可清理、内容变化定位、免登录 | 待实施 |
| 7 | 纠错/简单反馈与分享、主题订阅 | 用户确认私有反馈为主、另留 GitHub 讨论链接；公开卡片与订阅无草稿 | 待实施 |

保持 2 核/2GB 部署基线：正式服务器不安装应用开发依赖，图片处理交给七牛，优先使用现有 MySQL/Redis。公开内容缓存涉及隐藏/删除时必须失效；不以旧版本探活代替新版本发布验收。

第一轮只停用本地写入与目录依赖，保留既有文件和 Nginx 旧图片服务。正式删除要求审计结果 complete=true、旧引用为零，并核对上一成功版本及 Nginx 依赖；由实际发布验收决定。代码审计与隔离测试不能证明正式库的旧链接已经清零。

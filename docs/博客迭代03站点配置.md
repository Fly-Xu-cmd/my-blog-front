# 第三轮：站点配置

后台统一维护站点名称、作者称呼、站点简介、首页标题/介绍、头像、邮件、GitHub 和微信/QQ 二维码。空联系方式隐藏入口，首次迁移无配置行时沿用原站点内容；读取配置不自动写入数据库。

新增 SiteSettings 与独立兼容迁移。管理员读取和保存先验证 JWT，no-store；CAS revision 防止其他窗口覆盖。省略字段保留原值，空字符串清空可选入口。图片地址仅允许 http/https 或安全的 /imgs/ 路径，拒绝脚本协议、凭据 URL 和路径穿越。配置文字按普通文本渲染，JSON-LD 使用统一安全序列化。

根布局在服务端读取配置，更新后下次请求同步反映到 Header、Footer、首页、关于页头像、metadata、JSON-LD 作者、RSS 及订阅说明。React cache 仅合并同一服务端渲染内的读取；全站页面使用动态渲染，不新增跨请求永久缓存。配置故障保留阅读正文、使用默认站点身份并隐藏联系方式；管理 API 返回503，后台加载失败禁保存，保存失败保留输入。

后台沿用 AntD Form、Upload、Card 与现有主题；读取、上传、保存和离开有状态保护，未保存的外部图片不会自动加载。上传仍使用七牛接口。

## 旧图片与发布

新增字段也可能引用旧上传图片。发布前除当前正文与版本快照审计外，运行 `AUDIT_DATABASE_URL=... pnpm exec tsx scripts/audit-site-references.ts --output=site-reference-audit.json`，受限只读连接、5秒查询、180秒进程截止，不输出配置文案或地址凭据。无完整正式审计前不得删除旧 uploads 或 Nginx 映射。

API及迁移先发布，后台兼容检查要求 site-settings-v1。正式服务器仍接收 standalone 生产包，不安装开发依赖。回滚保留新表和配置，回退上一兼容应用；不回退鉴权。

## 验收

自动化：Linux Node24全套45项、typecheck/lint/build与standalone迁出源码smoke通过。后台Linux Node24 Jest26项、tsc、biome lint、兼容及Basic Auth探活6项通过，静态构建通过。主机全套Jest曾因旧系列用例15秒超时失败，隔离Linux全套已通过；未修改旧用例或掩盖失败。

隔离联测：Chromium22项通过，包括配置保存、无JS首屏/metadata/RSS、隐藏联系方式、移动端宽度与现有CRUD。测试构建初次用错API环境变量导致登录失败，改为仓库实际的BLOG_API_BASE_URL后重验通过。新增实际只读审计回归检查路径匹配、无配置文案/邮箱/签名输出且数据未变。

正式数据库、备份恢复、上线和真实七牛上传未验收。

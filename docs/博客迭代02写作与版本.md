# 第二轮：写作恢复与文章版本

2026-11-19。前后台独立 PR，目标 main；API 与数据库结构先发布，后台兼容检查要求 post-revisions-v1 后才部署。正式迁移仍按既有备份恢复要求执行，未访问正式库。

## 浏览器草稿

新增文章页与文章管理编辑器按 API 地址、管理员账号、文章区分草稿。不保存 token，不跨账号恢复；各窗口有独立草稿记录，恢复时复制到本窗口，仅当旧记录未被其他窗口更新才清理旧记录。发现旧草稿时由作者选择恢复或丢弃，不会覆盖新读入的服务器正文。浏览器空间不足或禁止存储时显示失败提示，服务器保存仍可操作。

创建请求前同步保存内容和 UUID 幂等键；响应丢失后刷新恢复，原内容与发布意图的重试沿用键，修改请求内容后换键。离开页面/刷新有提示，保存和上传时限制冲突操作；保存成功仅清理本窗口草稿。草稿包含私有正文，使用共享电脑时应丢弃不需要的记录；该数据仅在当前浏览器，不跨设备同步。

## 私有服务器版本

Post 新增 revision，旧文章默认 1，无全库正文复制。PostRevision 保存标题、正文、摘要、封面，创建与幂等结果同事务；第一次修改旧文章先记录原版本，每次服务器保存记录新版本。快照不含 URL、发布状态、分类、标签或系列，载入历史仅替换文章内容；作者检查后手动保存才生效。隐藏/再发布保留首次发布时间。

GET /api/posts/:slug/versions 分页返回版本号、操作者和日期，不返回正文；GET /api/posts/:slug/versions/:revision 返回所选快照。两者必须管理员 header 身份、no-store；匿名无法通过历史接口读取任何正文。删除文章后历史保留，历史接口返回 404，不自动清理快照或创建幂等记录。

新版后台 PUT 必须携带已加载 revision；锁定记录后校验，旧窗口返回 409 POST_VERSION_CONFLICT，不覆盖当前输入。API 为兼容发布顺序暂时接受旧客户端省略 revision；新后台详情读取失败不能保存。系列重排/删除系列、分类删除、标签重命名/删除也使文章 revision 递增，旧编辑窗口不能覆盖最新安排或重建旧标签；版本列表可能因此不连续。分类/标签与系列锁先于文章锁，事务使用 ReadCommitted。

## 旧图片审计与回滚

历史快照可能保留已从当前正文移除的旧图片，包括已删除文章的快照。在第一轮当前内容审计之外，还须运行历史审计：

```sh
# 本地或隔离环境，通过受限 AUDIT_DATABASE_URL 只读连接；不要在正式服务器安装开发依赖。
pnpm exec tsx scripts/audit-writing-references.ts --output=writing-reference-audit.json
```

单连接快照、每批10行、查询5秒、总180秒进程截止、最多10000行；输出资源标识和旧路径，不输出正文或凭据。报告不完整、历史仍有旧路径时，不能删除旧 uploads/Nginx 映射。浏览器未提交草稿无法由数据库审计证明清零，也须核对。

回滚保留新增字段和私有历史表，不能删历史数据；可回退上一兼容 API/后台版本，不能回退鉴权保护。恢复历史使用当前文章的手动保存与版本校验，不能直接替换数据库或自动重新公开。
